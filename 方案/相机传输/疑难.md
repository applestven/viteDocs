## 相机传输报错：无法在ftp服务区中创建目录  电脑ftp 是没问题的 

### 1.配置/etc/vsftpd.conf

```bash
# =========================================================
# vsftpd - Sony 相机 FTP 上传配置
# =========================================================

# -------------------------
# FTP 监听
# -------------------------
listen=YES
listen_ipv6=NO

# -------------------------
# 禁止匿名登录
# -------------------------
anonymous_enable=NO

# -------------------------
# 允许本地 Linux 用户登录
# -------------------------
local_enable=YES

# 允许上传、创建目录、删除、重命名
write_enable=YES
# 设置ftp登录之后的根目录
local_root=/home/apple/ftp

# -------------------------
# 本地用户权限
# -------------------------

# 新建文件权限
file_open_mode=0666

# 新建目录权限：
# 0666 + umask 000 = 文件 666
# 目录会按照目录默认权限创建
local_umask=000

# -------------------------
# FTP 用户进入自己的 Home
# -------------------------

# apple 登录后默认进入：
# /home/apple
#
# 如果相机 FTP 目录填写 ftp
# 实际就是：
# /home/apple/ftp
chroot_local_user=NO

# -------------------------
# 被动模式
# -------------------------
pasv_enable=YES

# 被动端口范围
pasv_min_port=50000
pasv_max_port=50009

# 外网访问时告诉客户端使用这个公网 IP
pasv_address=139.199.192.179

# -------------------------
# 数据连接
# -------------------------

# 允许客户端使用被动模式
connect_from_port_20=YES

# -------------------------
# FTP 超时
# -------------------------

idle_session_timeout=600
data_connection_timeout=120

# -------------------------
# 本地用户上传
# -------------------------

# 防止某些 FTP 客户端上传后无法继续操作
allow_writeable_chroot=YES

# -------------------------
# 日志
# -------------------------

xferlog_enable=YES

# 记录详细 FTP 命令
# 用于排查 Sony 相机 MKD/CWD/STOR 问题
log_ftp_protocol=YES

# 日志文件
vsftpd_log_file=/var/log/vsftpd.log

# -------------------------
# 时间
# -------------------------
use_localtime=YES

# -------------------------
# UTF-8
# -------------------------
utf8_filesystem=YES
```

### 2.打印日志与权限排查

    ```bash
    sudo tail -f /var/log/vsftpd.log
    ```

### 3相机的设置

设置ftp登录之后的根目录 [配置文件](#1配置etcvsftpdconf)
local_root=/home/apple/ftp

创建的目录为  gk/xxx  注意不要使用/gk






## nextcloud在登录的时候 账号密码正确的情况下无法重定向正常跳转 刷新一下界面就会自动跳转到登录完成的界面  登录界面 http://139.199.192.179:8800/login?clear=1 就是没有https的

关键配置没有问题：

```js
'trusted_domains' => 
  array (
    0 => '10.147.47.20:8800',
    1 => '127.0.0.1',
    2 => '192.168.0.112:8800',
    3 => '139.199.192.179:8800',
    4 => '139.199.192.179'
  ),
  'datadirectory' => '/var/www/html/data',
  'dbtype' => 'mysql',
  'version' => '30.0.4.1',
  'overwrite.cli.url' => 'http://139.199.192.179:8800',
  'overwriteprotocol' => 'http',
  'forcessl' => false,
  'overwritewebroot' => '/',
```

检查了线上服务器的nginx代理配置问题重新配置：
问题就在这一行 : proxy_set_header Host $host;
``` conf
server {
    listen 8800;
    server_name nextcloud;

    location / {
        proxy_pass http://10.147.47.20:8800/;
        proxy_set_header Host $http_host; 
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $http_host;

        proxy_buffering off;
        client_max_body_size 10G;
    }
}
```
